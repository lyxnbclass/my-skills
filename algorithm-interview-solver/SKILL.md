# 算法题面试讲解

将算法题整理为既能学习、又能在面试中复述的标准答案。默认同时提供 Java 和 Python，两份代码必须使用相同的核心算法并保持行为一致。

## 解题流程

1. 完整读取题目、输入输出、数据范围和示例。
2. 判断题型、关键约束、边界情况和目标复杂度。
3. 选择适合面试表达的主要解法；如存在明显的朴素解法，可简要说明其瓶颈，再引出最优或更合适的解法。
4. 分别编写 Java 和 Python 完整代码。
5. 对照检查两份代码的算法、返回值、边界行为和复杂度是否一致。
6. 使用具体样例模拟关键变量的变化。
7. 生成可以直接复述的面试话术。

题目信息缺失且会改变算法选择时，先指出缺少的数据范围、输入格式或返回要求，并向用户询问。若只存在不影响核心解法的小歧义，明确写出最小假设后继续，不得偷偷补充题目条件。

## 固定输出结构

严格按照以下六个一级标题输出，不得调整顺序或合并章节。

### 1. 解读题意

- 用自己的话说明题目要求，避免机械复述原文。
- 明确输入、输出和需要满足的条件。
- 提炼数据范围对算法选择的影响；题目未给数据范围时明确说明。
- 列出空输入、单元素、重复元素、负数、溢出等与本题实际相关的边界情况，不罗列无关项目。

### 2. 核心思路

- 先用一句话概括所用算法或数据结构。
- 分步骤解释为什么这样做，而不只描述代码执行动作。
- 说明维护的状态、不变量或正确性依据。
- 如果有朴素解法，最多用一小段说明其问题，再引出推荐解法。
- 明确给出时间复杂度和空间复杂度，并解释复杂度来源。
- 不为显得高级而强行使用复杂算法；优先选择正确、清晰、适合题目约束的方案。

### 3. 完整代码

依次使用以下二级标题：

#### 3.1 Java

提供完整、可编译的 Java 代码。

#### 3.2 Python

提供完整、可运行的 Python 代码。

代码要求：

- 默认同时提供两种语言；只有用户明确要求单一语言时才可省略另一种。
- 两份代码必须实现第二节描述的同一个算法，变量含义和边界处理保持一致。
- 禁止使用省略号、伪代码或“此处略去”等占位内容。
- 保留题目指定的函数签名、类名和输入输出格式。
- 题目来自 LeetCode 且未要求控制台输入时，使用平台要求的 `Solution` 形式；普通笔试题则提供包含输入、输出处理的完整程序。
- Java 注意整数溢出、比较器溢出、泛型类型和必要的导入；Python 注意索引边界、可变对象和递归深度。
- 添加少量解释“为什么”的注释，不给每个显而易见的语法行添加噪声注释。

### 4. 逐行讲解

依次使用以下二级标题：

#### 4.1 Java 逐行讲解

按照代码出现顺序解释每条有实际语义的语句。可以把导包、花括号和连续声明等纯语法行合并说明，但不得跳过核心条件、循环、状态更新和返回语句。

#### 4.2 Python 逐行讲解

采用相同标准解释 Python 代码，重点说明 Python 特有写法。对于与 Java 完全相同的算法思想可以简洁引用，但仍要解释对应语句的作用。

讲解必须与第三节最终代码逐项对应；不得讲解已经删除的变量、旧版本逻辑或代码中不存在的步骤。

### 5. 具体样例

- 优先使用题目原有样例；若题目没有样例，再构造一个最小但能体现算法过程的样例。
- 写清输入和预期输出。
- 按关键步骤展示指针、数组、栈、队列、哈希表、动态规划状态等变量如何变化。
- 对循环次数很多的题目展示有代表性的步骤，并说明中间省略的是重复过程。
- 最后核对实际结果为何等于预期输出。

### 6. 面试话术

先给出一段约 30～60 秒、可以直接对面试官说的话，至少包含：

1. 对题目的理解；
2. 选择的数据结构或算法；
3. 关键执行过程或正确性依据；
4. 时间、空间复杂度；
5. 一个值得主动说明的边界情况。

随后补充 2～4 个本题最可能出现的追问及简短回答，例如为什么不用另一种算法、如何进一步优化、数据规模变化后怎么办、代码如何处理特殊输入。不要编造业务收益或性能数据。

## 输出前检查

在提交答案前检查：

- 六个一级章节是否齐全且顺序正确；
- Java、Python 是否都完整，并与核心思路一致；
- 函数签名和输入输出是否符合题目；
- 样例能否按代码得到所写结果；
- 时间、空间复杂度是否与实现相符；
- 逐行讲解是否覆盖所有核心语句；
- 面试话术是否自然、简洁且可以口头复述；
- 是否明确区分题目已知信息与自行作出的假设。
